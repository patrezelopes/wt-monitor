## wt-monitor v0.4.0 — CPU contention, priority control, resume and open in editor

### Added
- **Resume a session in a new terminal.** A *Resume session* button in the session drawer runs `claude --resume <id>` for the worktree's most recent conversation, even if Claude has already exited. The session id is read from the transcript file name on the server, never from the request.
- **Open a worktree in your editor.** An *Open in code* button launches VS Code (or Cursor, VSCodium, Windsurf, Zed, or `WT_EDITOR`) on the worktree.
- **CPU contention, always on.** Per-worktree *queue %* (time waiting for a core) and system CPU/memory pressure (PSI), plus a new *CPU contended* alert.
- **Priority control (opt-in, `--control`).** A *Priority* tab: CPU level, **Focus** on one worktree, soft memory limit and protection, via cgroup v2. Reversible; nothing is ever killed.
- `examples/`: generic skills and agents (PO intake, Agile coach, agent orchestration).

### Changed
- `make install` now enables terminals and priority control by default (`TERMINALS=` / `CONTROL=` empty to opt out).
- The Activity tab renders Markdown and Claude Code's XML-like tags.
- CPU is shown as a percentage of the whole machine.

Upgrade: `git pull && make install`. Full list in the [CHANGELOG](https://github.com/patrezelopes/wt-monitor/blob/main/CHANGELOG.md).
